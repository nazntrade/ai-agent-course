# Неделя 2 — День 7. Сохранение контекста

Streamlit-приложение «Первый агент» развивается: контекст теперь хранится в **SQLite** и переживает перезапуск приложения. Вместо одной сессии появилось несколько независимых чатов со своими настройками и счётчиками токенов, как список диалогов в ChatGPT.

## Что умеет приложение

- показывать в сайдбаре список сохранённых чатов (новые — сверху);
- создавать новый чат, выбирать существующий, удалять чат только после явного подтверждения;
- после перезапуска автоматически открывать **последний выбранный** чат;
- восстанавливать историю каждого чата из SQLite — разговор продолжается так, словно приложение не выключалось;
- не смешивать истории разных чатов;
- формировать название нового чата из первого сообщения пользователя (без обращения к LLM);
- хранить для каждого чата собственные настройки: system prompt, модель, temperature, max tokens, режим потокового вывода;
- вести для каждого чата счётчики входных/выходных/общих токенов на основе реального `usage` API (если провайдер метрику не вернул — показывается «нет данных», ничего не выдумывается);
- поддерживать и потоковый, и непотоковый режимы ответа (в настройках чата).

Осознанно не добавлялись: саммаризация, векторная база, embeddings, семантический поиск и выбор релевантных сообщений. На этом этапе полная упорядоченная переписка сохраняется целиком и целиком передаётся модели.

## Как устроено хранение

Хранение — отдельная ответственность (`storage.py`), в Streamlit-интерфейсе нет SQL. `ChatAgent` остаётся отдельной сущностью и по-прежнему отвечает за стек сообщений, добавление system prompt, передачу полной истории в LLM, вызов API, потоковую сборку ответа и обновление контекста после успешного ответа.

База: `week-02/first-agent/data/chat_history.db`. Путь вычисляется относительно файлов проекта и не зависит от текущей директории запуска. Сопутствующие файлы `-wal` и `-shm` (режим WAL) и сам файл базы не попадают в Git (добавлены в корневой `.gitignore`).

Схема SQLite:

- `chats` — чат: название, настройки (`system_prompt`, `model`, `temperature`, `max_tokens`, `stream`), накопительные `input_tokens`/`output_tokens` (NULL = «нет данных»);
- `messages` — сообщения (`user`/`assistant`), привязка к чату со `ON DELETE CASCADE`;
- `app_state` — служебные ключи, включая последний выбранный чат.

Целостность истории:

- пустой запрос не обращается к API;
- при ошибке API частичный ответ не сохраняется;
- пара «user + assistant» и обновление токенов пишутся одной транзакцией (`save_turn`);
- удаление чата удаляет его сообщения (каскадно);
- если база пуста, приложение показывает пустое состояние с кнопкой «Создать чат» — первый чат создаётся по действию пользователя;
- повторная инициализация схемы безопасна (`CREATE TABLE IF NOT EXISTS`).

## Структура проекта

- `agent.py` — агент как отдельная сущность, **не зависит от Streamlit**:
  - `get_client()` — клиент DeepSeek API по `DEEPSEEK_API_KEY` из `.env`;
  - `AgentConfig` — `model`, `system_prompt`, `temperature`, `max_tokens`, `stream`;
  - `ChatAgent(client, store=None, chat_id=None, config=None)` — при наличии `store` агент привязан к чату: при создании загружает настройки и историю из базы, `set_config()` сохраняет изменённые настройки, `ask()` отправляет в API всю историю выбранного чата, собирает потоковый или обычный ответ и после успеха атомарно сохраняет реплику и `usage`. Без `store` работает как прежде, только в памяти. Ошибка API откатывает добавленное сообщение и ничего не пишет в базу.
- `storage.py` — `ChatStore`, SQLite-хранилище (схема, создание/загрузка/список/удаление чатов, настройки, сообщения, последний выбранный чат, токены). Модуль независим от `agent.py` (duck-typed контракты).
- `app.py` — Streamlit-интерфейс: список чатов, создание/удаление с подтверждением, авто-открытие последнего чата, настройки выбранного чата, счётчики токенов, потоковая печать ответа и индикатор ожидания.
- `tests/test_agent.py` — тесты агента (unittest, моки, **без реальных сетевых запросов** и без чтения `.env`).
- `tests/test_storage.py` — тесты хранилища на временной базе.
- `requirements.txt` — зависимости: `openai`, `python-dotenv`, `streamlit` (SQLite — стандартная библиотека).
- `run_app.bat` — запуск приложения двойным щелчком.
- `.env.example` — образец `.env` без настоящего ключа.

Запуск тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

## Первый запуск

Откройте PowerShell в папке проекта (`week-02\first-agent`) и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В открывшемся файле замените `your_api_key_here` своим ключом DeepSeek и сохраните файл.

## Запуск приложения

После первоначальной настройки запустите двойным щелчком:

```text
run_app.bat
```

Либо выполните в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

> Файл `.env` содержит секретный API-ключ и не загружается в GitHub благодаря `.gitignore`. Файл базы `data/chat_history.db` и его `-wal`/`-shm` тоже исключены из Git.

## Демонстрация: память между чатами и после перезапуска

1. Нажмите «➕ Создать чат» и отправьте в первом чате: «Меня зовут Андрей».
2. Нажмите «➕ Создать чат» ещё раз и спросите во втором чате: «Как меня зовут?» — новый чат не знает вашего имени, истории не смешиваются.
3. Вернитесь в первый чат и снова спросите: «Как меня зовут?» — история сохранилась, имя известно.
4. В первом чате измените настройки (например, system prompt и temperature) — они применяются к следующим запросам и не влияют на другие чаты.
5. Перезапустите приложение (`run_app.bat`).
6. Откроется последний выбранный чат, история и настройки восстановятся из SQLite.
7. Спросите имя — ответ придёт из сохранённого контекста.
8. В сайдбаре виден счётчик токенов чата (ввод/вывод/всего; «нет данных», если провайдер не вернул метрику).
9. Удалите один чат через «Удалить чат» с подтверждением — остальные чаты не пострадают.
