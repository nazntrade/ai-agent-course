# Неделя 2 — День 8. Работа с токенами

Streamlit-приложение «Первый агент» продолжает развиваться. Контекст по-прежнему хранится в **SQLite** и переживает перезапуск, но теперь для каждого обращения к модели сохраняется и показывается подробная статистика: сколько токенов ушло на сообщение, на полный отправленный контекст, на ответ, сколько провайдер вернул по кэшу, почему завершился ответ и сколько это примерно стоило.

День 8 ничего не удаляет из поведения Дней 6–7: несколько независимых чатов, создание/удаление, восстановление последнего выбранного чата, индивидуальные настройки, пустое стартовое состояние, потоковый и непотоковый режимы, индикатор ожидания и откат при ошибке сохранены.

## Что умеет приложение

- показывать в сайдбаре список сохранённых чатов (новые — сверху) и компактный накопительный расход по каждому чату;
- создавать, выбирать и удалять чат (удаление — только после явного подтверждения);
- восстанавливать последний выбранный чат и всю его историю со статистикой из SQLite;
- хранить для каждого чата собственные настройки: system prompt, модель, temperature, max tokens, потоковый вывод и **демо-лимит контекста**;
- показывать у каждого сообщения пользователя оценочное число токенов именно этого сообщения;
- показывать у ответа ассистента токены ответа и компактную строку завершённого обращения: контекст, всего, cache hit/miss, оценочная стоимость, `finish_reason`;
- показывать подробную статистику текущего чата и таблицу всех его ходов в раскрывающихся блоках;
- показывать сравнение диалогов (накопительный расход против уникальной истории);
- безопасно демонстрировать переполнение контекста через демо-лимит, не отправляя запрос в API.

Осознанно не добавлялись: RAG, векторная база, TOON, автоматическая обрезка или сжатие истории, summary memory, LangChain, новые провайдеры. Полная упорядоченная переписка по-прежнему сохраняется целиком и целиком передаётся модели.

## Токены: что чем измеряется

Важно не смешивать несколько разных величин.

| Показатель | Что это | Источник |
|---|---|---|
| Токены сообщения | Размер только последнего сообщения пользователя | локальная оценка, помечается `≈` |
| Контекст запроса | Всё, что фактически ушло модели: system prompt + вся предыдущая история + новое сообщение | точное `prompt_tokens` из `usage` API |
| Токены ответа | Сколько модель сгенерировала | точное `completion_tokens` из `usage` API |
| Токены обращения | Сумма входа и выхода за один ход | точное `total_tokens` из `usage` API |
| Накопительный расход чата | Сумма входных и выходных токенов по всем ходам | сумма точных значений API |
| Уникальная история | Примерный размер сохранённых сообщений в базе | локальная оценка, помечается `≈` |
| Стоимость | Оценочная стоимость одного хода и всего чата | расчёт по точным токенам и тарифу |

### История отправляется повторно

Каждый запрос отправляет модели **всю** историю чата заново, а не только новое сообщение. Поэтому накопительный расход API растёт значительно быстрее, чем размер уникальной истории в базе: каждое новое обращение оплачивает весь предыдущий контекст ещё раз. Именно это сравнение видно в блоке «Сравнение диалогов».

### Точные и оценочные значения

- Значения из `usage`, которые вернул провайдер, считаются **точными** и выводятся без пометки.
- Локально рассчитанные значения помечаются знаком `≈` и подписываются как оценка. Оценка никогда не выдаётся за официальный результат API и не используется для расчёта денег.
- Если провайдер не вернул поле, показывается «нет данных». Ничего не выдумывается.

Локальная оценка токенов (`tokens.py`) — детерминированная эвристика без внешних зависимостей: кириллица считается «дороже» латиницы. Она достаточно точна по порядку величины для учебного сравнения, но это не токенизатор.

### Cache hit / cache miss

Провайдер может вернуть `prompt_cache_hit_tokens` и `prompt_cache_miss_tokens` — сколько входных токенов взято из кэша и сколько обработано заново. Кэшированный ввод тарифицируется заметно дешевле. Если разбивка есть, стоимость считается по двум разным ставкам; если её нет — весь вход консервативно оценивается по ставке cache miss, и это явно указано в поле «допущение».

## Стоимость

Стоимость всегда **оценочная** (`≈`). Тарифы хранятся централизованно в `pricing.py`, а не в интерфейсе или бизнес-логике. Расчёт идёт только от точных токенов API: если точных значений нет, стоимость не показывается.

- Источник официальных тарифов: <https://api-docs.deepseek.com/quick_start/pricing>, проверено **2026-09-10**.
- Легаси-имя `deepseek-v4-flash` обслуживается моделью DeepSeek-V4.1-Flash и тарифицируется по цене Flash.
- Есть peak- и off-peak-окна: 01:00–04:00 и 06:00–10:00 UTC по будням (peak), остальное время — off-peak.
- Если для введённой модели тариф неизвестен, показывается «тариф неизвестен»; цена не придумывается.

## Лимит ответа и переполнение контекста — это разные вещи

- **`max_tokens`** ограничивает только длину генерируемого ответа. Если модель остановилась из-за этого, приходит `finish_reason="length"`, а интерфейс поясняет: достигнут лимит длины ответа, а не лимит всего контекста.
- **Переполнение контекстного окна** означает, что входной контекст вместе с запрошенным ответом не помещается в лимит модели. Запрос в этом случае отклоняется, и это настоящая ошибка, а не штатное завершение.

Никакой автоматической обрезки, сжатия или скрытого удаления истории нет: День 8 должен именно показать проблему переполнения.

### Безопасный демо-лимит

Чтобы демонстрировать переполнение, не тратя реальные токены, у каждого чата есть настройка **«Демо-лимит контекста, токены»** (`0` = выключен). Перед запросом приложение локально оценивает вход и складывает его с `max_tokens`:

- если сумма превышает демо-лимит — показывается понятное предупреждение, а запрос в API **не отправляется**; история и база не меняются;
- реальная ошибка превышения контекста от API (если она всё же произошла) показывается отдельно, с текстом провайдера; история также откатывается, частичный ответ не сохраняется.

## Как устроено хранение

Хранение — отдельная ответственность (`storage.py`), в Streamlit-интерфейсе нет SQL. `ChatAgent` отвечает за стек сообщений, вызов API, сбор `usage`/`finish_reason` и откат при ошибке.

База: `week-02/first-agent/data/chat_history.db`. Схема:

- `chats` — чат: название, настройки (`system_prompt`, `model`, `temperature`, `max_tokens`, `stream`, `demo_context_limit`), накопительные `input_tokens`/`output_tokens`, `history_tokens_est` (≈ уникальная история), `cost_usd` (≈ накопительная стоимость); `NULL` означает «нет данных»;
- `messages` — сообщения (`user`/`assistant`) с привязкой к чату (`ON DELETE CASCADE`);
- `turns` — статистика одного обращения: связь с парой сообщений, оценка токенов сообщения, точные `request_tokens`/`response_tokens`/`total_tokens`, cache hit/miss, `finish_reason`, `cost_usd`, `cost_assumption`, время;
- `app_state` — служебные ключи, включая последний выбранный чат.

Целостность:

- пустой запрос не обращается к API;
- при ошибке API частичный ответ не сохраняется;
- сообщения пары, строка `turns` и обновление накопительных счётчиков пишутся **одной транзакцией**: при сбое API или записи в базу не остаётся частичных сообщений, неверных счётчиков или незавершённого хода;
- удаление чата каскадно удаляет его сообщения и статистику ходов;
- **миграция старой базы Дня 7** идемпотентна: при первом открытии добавляются таблица `turns` и новые колонки, существующие чаты и сообщения не удаляются. Для старых сообщений точной статистики нет — интерфейс честно показывает «статистика хода: нет данных», а размер уникальной истории для старых чатов помечается как оценка `≈`.

## Структура проекта

- `tokens.py` — детерминированная локальная оценка токенов (stdlib, без зависимостей).
- `stats.py` — нейтральные контейнеры `TurnStats` и `AskResult`; не тянут зависимости агента, хранилища или UI.
- `pricing.py` — централизованные тарифы, peak/off-peak и расчёт оценочной стоимости.
- `agent.py` — агент как отдельная сущность, **не зависит от Streamlit**:
  - `get_client()` — клиент DeepSeek API по `DEEPSEEK_API_KEY` из `.env`;
  - `AgentConfig` — `model`, `system_prompt`, `temperature`, `max_tokens`, `stream`, `demo_context_limit`;
  - `ChatAgent.ask(...) -> AskResult` — демо-предпроверка до API, отправка полной истории, сбор точного `usage`/`finish_reason` (stream и non-stream), локальные оценки, расчёт стоимости, атомарное сохранение и откат при ошибке; исключения `ContextLimitError` (демо-лимит) и `ApiContextOverflowError` (реальная ошибка провайдера).
- `storage.py` — `ChatStore`: схема и миграция, чаты, настройки, сообщения, статистика ходов, накопительные счётчики, последний выбранный чат.
- `app_logic.py` — чистые помощники интерфейса без зависимости от Streamlit: сравнение настроек (учитывает, что `None` и `0` демо-лимита — это одно и то же «выключено») и управление спиннером ожидания для потокового режима.
- `app.py` — Streamlit-интерфейс: список чатов с расходом, настройки, сообщения с токенами, раскрывающиеся блоки «Статистика текущего чата» и «Сравнение диалогов», обработка ошибок.
- `tests/` — `test_agent.py`, `test_storage.py`, `test_tokens.py`, `test_pricing.py`, `test_app_logic.py` (unittest, моки, **без реальных сетевых запросов**, без настоящего ключа и без чтения `.env`).
- `requirements.txt` — зависимости: `openai`, `python-dotenv`, `streamlit` (SQLite и математика — стандартная библиотека; новых зависимостей нет).
- `run_app.bat` — запуск приложения двойным щелчком.
- `.env.example` — образец `.env` без настоящего ключа.

## Первый запуск

Откройте PowerShell в папке проекта (`week-02\first-agent`) и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В открывшемся файле замените `your_api_key_here` своим ключом DeepSeek и сохраните файл.

## Запуск приложения

Двойным щелчком:

```text
run_app.bat
```

Либо в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

## Демонстрация: короткий, длинный и переполненный диалог

Короткий диалог:

1. Нажмите «➕ Создать чат» и отправьте короткое сообщение, например «Привет».
2. Под сообщением появится `≈ N ток. сообщения (оценка)`.
3. Под ответом — точные токены ответа и строка хода: контекст, всего, cache hit/miss, `≈` стоимость, `finish_reason`.
4. Раскройте «Статистика текущего чата» — там итоги и таблица ходов.

Длинный диалог:

5. Продолжайте задавать вопросы в том же чате. С каждым ходом «контекст» растёт: история отправляется заново целиком.
6. Раскройте «Сравнение диалогов» и сравните «Накопленный вход» с `≈` «Уникальная история» — накопительный расход растёт быстрее.

Лимит ответа (`max_tokens`), не путать с контекстом:

7. В настройках чата задайте маленький `Max tokens` (например, 20) и попросите длинный ответ.
8. Под ответом появится `finish: length` и пояснение, что достигнут лимит длины ответа, а не контекста.

Переполнение контекста (безопасно, без реального запроса):

9. В настройках чата задайте `Max tokens` = 50 и «Демо-лимит контекста» = 200.
10. Отправляйте сообщения, пока локальная оценка входа + `max_tokens` не превысит лимит. Приложение покажет предупреждение и **не отправит** запрос; история и база не изменятся.
11. Чтобы снять ограничение, верните «Демо-лимит контекста» в `0`.

Стоимость и неизвестный тариф:

12. В настройках чата можно изменить модель. Для неизвестной модели стоимость показывается как «тариф неизвестен».

## Исправления после Дня 8

- При выключенном демо-лимите (`0` в интерфейсе, `None` в конфиге) обычный rerun больше не сохраняет настройки повторно: `None` и `0` считаются одним и тем же «выключено», а сохранение происходит только при реальном изменении любого поля. Переключение лимита `0 → положительное → 0` по-прежнему сохраняется.
- В потоковом режиме во время ожидания показывается спиннер «Ожидание ответа...» (поверх скелетон-плейсхолдера). После первого фрагмента спиннер исчезает, и вывод продолжается потоково; при ошибке или срабатывании демо-лимита спиннер также убирается. Непотоковый режим со своим индикатором не изменился.

## Ограничения и оговорки

- Локальная оценка токенов — эвристика, а не токенизатор; она может заметно отличаться от точных значений и всегда помечается `≈`.
- Демо-лимит проверяется по оценкам, поэтому его срабатывание приблизительное; настоящую защиту обеспечивает ошибка API, которая показывается честно.
- Определение реального переполнения контекста опирается на признак ошибки провайдера (`status_code` 400 и упоминание context); при другой формулировке ошибка покажется как обычная, без падения.
- Стоимость старых ходов, у которых нет точной статистики, не восстанавливается — для них «нет данных».
- Тарифы привязаны к официальной таблице DeepSeek на дату проверки; при изменении цен правится только `pricing.py`.

> Файл `.env` содержит секретный API-ключ и не загружается в Git благодаря `.gitignore`. Файл базы `data/chat_history.db` и его `-wal`/`-shm` тоже исключены из Git.
