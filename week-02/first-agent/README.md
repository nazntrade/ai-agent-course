# Неделя 2 — День 6. Первый агент

Небольшое Web-приложение на Python и Streamlit: агент принимает сообщение пользователя, отправляет запрос в DeepSeek API и потоково выводит ответ. Впервые работа с LLM и история сообщений вынесены в отдельную сущность — агента (`ChatAgent`), который не зависит от Streamlit и тестируется отдельно.

## Что делает агент

- принимает сообщение пользователя;
- отправляет запрос в LLM через DeepSeek API (`DEEPSEEK_API_KEY` из `.env`);
- получает и потоково выводит ответ;
- хранит историю текущей сессии и при каждом запросе передаёт LLM всю предыдущую историю — поэтому агент «помнит» контекст диалога;
- умеет очищать историю (кнопка в интерфейсе).

Интерфейс только принимает сообщения, вызывает агента и отображает результат. Вся логика работы с LLM и история сообщений инкапсулированы внутри агента.

## Структура проекта

- `agent.py` — агент как отдельная сущность. Модуль **не зависит от Streamlit** и тестируется отдельно:
  - `get_client()` — читает `DEEPSEEK_API_KEY` из `.env` и возвращает клиент DeepSeek API (или `None`, если ключ не задан);
  - `AgentConfig` — конфигурация агента: `model`, `system_prompt`, `temperature`, `max_tokens`, `stream`;
  - `ChatAgent` — инкапсулирует историю сообщений (`history` возвращает копию), `clear()` сбрасывает её к одному системному сообщению, `ask(user_message, on_chunk=None)` добавляет сообщение пользователя, отправляет всю историю в API, потоково собирает ответ через `on_chunk` и только при успехе сохраняет полный ответ ассистента. При ошибке API добавленное сообщение пользователя откатывается, а частичная реплика ассистента в историю не попадает.
- `app.py` — Streamlit-интерфейс: лента чата, поле ввода, потоковый вывод ответа, кнопка «Очистить историю» в сайдбаре (там же показан используемый system prompt). Клиент и агент хранятся в `st.session_state`.
- `tests/` — автоматические тесты агента на `unittest` с моками, **без реальных сетевых запросов**:
  - начальное системное сообщение в истории;
  - добавление сообщения пользователя;
  - сохранение полного ответа ассистента (склейка из чанков);
  - передача предыдущей истории при следующем запросе;
  - очистка истории;
  - обработка пустого ввода (без обращения к API);
  - сохранность истории при ошибке API (откат, нет частичной реплики);
  - применение конфигурации агента (model, system prompt, temperature, max_tokens, stream);
  - потоковый вызов `on_chunk` с накопленным текстом.
- `requirements.txt` — зависимости: `openai`, `python-dotenv`, `streamlit`.
- `run_app.bat` — запуск приложения двойным щелчком.
- `.env.example` — образец файла `.env` без настоящего ключа.

Запуск тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

## Первый запуск

Откройте PowerShell в папке проекта (`week-02\first-agent`) и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В открывшемся файле замените `your_api_key_here` своим ключом DeepSeek и сохраните файл.

## Запуск приложения

После первоначальной настройки запустите двойным щелчком:

```text
run_app.bat
```

Либо выполните в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

> Файл `.env` содержит секретный API-ключ и не загружается в GitHub благодаря `.gitignore`.

## Демонстрация памяти агента

Агент передаёт LLM всю историю текущей сессии, поэтому он «помнит» сказанное ранее. Проверьте это так:

1. Отправьте: «Меня зовут Андрей».
2. Спросите: «Как меня зовут?» — агент ответит, что вас зовут Андрей, потому что в запрос попала предыдущая реплика.
3. Нажмите «Очистить историю» — история сброшена до одного системного сообщения.
4. Снова спросите: «Как меня зовут?» — теперь агент не знает вашего имени, так как предыдущий диалог в запрос больше не передаётся.
