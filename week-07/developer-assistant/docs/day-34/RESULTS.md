# D34 — Измеренные результаты и ограничения

Проверенные реальные Local и DeepSeek запуски охватывают сохранённый impact report,
обновление документации и адаптацию клиента. Отдельно проверены чистый impact repeat,
no-op на обновлённых docs/client, guarded application/recovery и Stop. Это результаты
конкретных целей и исходных состояний, а не гарантия успеха произвольного задания.

## Исходная версия и проверки

Backend полного независимого offline прогона **208 PASS** — `19657210`. Последний
UI snapshot `5930fa1b` прошёл независимый source review и **50 workflow PASS + smoke
1 PASS** при неизменных backend bytes. Наборы перекрываются: это не 258 разных
проверок. Текущий discoverable suite содержит 209 тестов; полный прогон всех 209
на последнем UI snapshot не заявляется. Итоговое изменение документации не меняет
эти проверенные engine/UI/test bytes.

Проверки используют настоящий SDK MCP; scripted provider и synthetic private payload
в offline контролях явно отделены от LIVE. Static, trusted behavior, application,
качество текста и оценка исходной цели — самостоятельные результаты.

`elapsed_s` начинает измеряться до ожидания общего service lock и включает очередь.
Числа выше — сохранённые поля запусков, не чистое время inference и не сравнительный
benchmark скорости моделей. 18k/40k/100k обозначают символы host envelope, не tokens
или физическое окно модели. Параметры выбранных моделей не повышались автоматически.

Компактные impact и code-only цели уточняют желаемый объём, сохраняя требования к
фактам и публичному контракту. Их успех не переименовывает прежние широкие неудачи.
DeepSeek code-only run использовал копию с двумя заранее применёнными docs-правками;
они не являются результатом клиентского запроса. Документационные цели выполнялись
на своих зафиксированных копиях.

В Local compact impact весь сохранённый 16-строчный отчёт получен реальным
`get_diff`; отдельного post-write `read_file` и модельного вызова tests не было.
Whole-output review сравнивал весь отчёт с источниками. Новый файл имеет SHA-256
`f0722ff18581e99f3aa58523b1629f619d8b981eddeaa1c84c5c6a534e7b36af`.

`bbb8da0322e305d784d872764f804a9d6b0146153983a8d8ef166bfb32e9f7af`.

## Реальные операции и сохранность данных

- После реального Apply и частичного Undo под OS file lock сравнивалось всё дерево
  девяти файлов. UI немедленно показал `PARTIAL_OR_UNCERTAIN` и Recover без reload,
  сохранив оригинальную ошибку. Собственный restart/Recover вернул целое состояние
  **перед Undo** — две уже применённые docs-правки, а не первоначальный baseline.
- На обновлённом клиенте normal review/Apply дал NOOP journal с пустым files;
  marker предыдущей реально применённой клиентской batch остался доступен для Undo.
  На обновлённых документах фактический Diff пуст.
- Реальные source/target conflicts сохранили foreign markers; после проверки всё
  дерево девяти файлов восстановлено. Stop отменил активный запуск; более 280 секунд
  наблюдения, смена проекта и reload не показали поздних записей.

Эти проверки относятся к конкретным исполненным состояниям. Catchable staging
cleanup не гарантирует очистку произвольного hardkill во время создания temp file.
Многофайловая запись не объявляется единой атомарной транзакцией файловой системы.

## Сохранённые отрицательные результаты

| Случай | Зафиксированное ограничение |
| --- | --- |
| Ранние 18k/40k цели | Были protocol/context failures, reread loops, нулевые drafts и неверные фактические утверждения. Полный обязательный envelope не обрезается ради успеха |
| DeepSeek output exhaustion | Несколько реальных запросов не дали draft. Точный вклад private reasoning/tool payload не установлен: полное private содержимое не сохранялось |
| Local длинный impact | 897,83 с, незавершённый draft около 15k символов и parse FAIL |
| Local предшествующий compact impact | 818,47 с, parse FAIL, 0 draft |
| Прежний docs repeat | 80,09 с, output length, 0 draft |
| Прежний client repeat | 75,36 с; код без изменений и 20 vectors PASS, но незапрошенный audit 7232 bytes. Strict no-op FAIL сохранён |
| Старый checker/UI | Ошибочные прежние predicates и stale APPLIED после ошибки Undo сохранены как отрицательные наблюдения; исправленные проверки не редактируют model draft и не стирают старые FAIL |

Нет скрытого Local↔DeepSeek fallback. `completed`, static/behavioral PASS и наличие
файла не принимаются за независимую проверку содержания. `NOT_ASSESSED` означает
отсутствие соответствующей оценки. TicketDesk — чистый Python fixture; его vectors
не доказывают поведение развёрнутого HTTP-сервиса или произвольного проекта.
Lifecycle настоящей Local-модели и сохранность borrowed runtime проверяются отдельно.
