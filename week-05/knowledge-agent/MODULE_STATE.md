## Архитектура и данные

- Python/FastAPI/Pydantic, SQLite, static HTML/JS/CSS без сборки/CDN.
- Документы → SourceAdapter → chunking fixed/structure → embeddings → индекс D21.
- ChatService обеспечивает retrieval/filter/rewrite/контекст/цитаты D22–D24.
- ConversationService + ConversationStore добавляют D25: историю, подтверждённый task-state,
  разрешение отсылок, атомарную запись/идемпотентность, пагинацию и изоляцию диалогов.
- Индекс и разговоры в разных БД. Пользовательские сообщения — основания памяти;
  документальные цитаты — основания фактов ответа. Сохранённые источники привязаны к ходу.
- D25: бюджет выбранного remote 32768/8192 отдельный; local автоматически 16k/3072 ограничен
  реальным окном. Без выбранного профиля сохранены существующие CHAT-настройки;
  явно заданные несовместимые лимиты отклоняются. Прежние значения одиночного API 8192/1024 сохранены.
- Канонические требования: `docs/specs/day-25-rag-chat-memory/`; ожидания A/B в `eval/d25/`.
- Корпус, БД, сырые LIVE-результаты и диагностика игнорируются Git; секреты не публикуются.

## Работа агентов

Обязательное ядро — корневой AGENTS.md, процедуры — `.opencode/WORKFLOW.md`, факты/доверенные
команды — PROJECT_RULES.md и MODULE_RULES.md. Выбранный allowed-профиль уже разрешает
ограниченные обязательные LIVE без вопроса; forbidden запрещает их без fallback.
Без положительного ДЕЛАЕМ подготовка заканчивается ожиданием решения; с ДЕЛАЕМ проходит
полный цикл. Следующую задачу выводить из запроса пользователя, не из старых статусов D22.

Приёмка требует полного чтения результата, независимого сопоставления с источниками и
обязательными критериями. Технический PASS не заменяет качество. Tester сохраняет свои
объявленные доказательства через create-only tester_evidence в Центре; код/тесты не меняет.
Новые проверки не используют рабочую БД и не останавливают чужие процессы/заимствованные модели.
