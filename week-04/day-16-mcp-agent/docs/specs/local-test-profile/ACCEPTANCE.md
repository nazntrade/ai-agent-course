# Приёмка локального профиля тестов

- AC-LTP-1 [LTP-1, LTP-2]: любой частичный/неверный профиль даёт `BLOCKED`; выбранный remote model id и endpoint видны в отчёте, локальный launcher не вызывается, реальный ответ модели подтверждён. Недоступность не приводит к Qwen fallback.
- AC-LTP-2 [LTP-1, LTP-3]: выбранный local alias проверяется у `/v1/models`, ID вычисляется из выбранного пути, а `/props.model_path` совпадает с этим же GGUF; расхождение даёт `BLOCKED`; один parent-owned launcher живёт весь acceptance и закрывается ровно один раз в `finally` при успехе/ошибке; panel-owned endpoint не закрывается harness.
- AC-LTP-3 [LTP-4]: deterministic E2E используют fake поиск без платного вызова; opt-in end-to-end подтверждает реальный Tavily-вызов через MCP и ответ с URL, отсутствие ключа/вызова не выдаётся за PASS.
- AC-LTP-4 [LTP-5]: тестовые процессы не читают `.env`; stdout/stderr фильтруются до сохранения, вложенный отчёт фильтруется до сериализации, в trace, логах, отчёте, run artifacts и командной строке нет секретов и полного пути модели; `test.bat unit` и мок-регрессии проходят; при доступном разрешённом API проходят реальный remote inference и Tavily; VPS и `run_app.bat` неизменны.
