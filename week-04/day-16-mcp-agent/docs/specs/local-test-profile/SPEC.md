# Локальный профиль тестового прогона

## Область действия

Только доверенный локальный запуск `test.bat` и его дочерние тестовые процессы. Поведение `run_app.bat`, приложения и VPS не меняется.

## Требования

- LTP-1. Наличие любой переменной `AI_TEST_MODEL_*` включает fail-closed профиль. Требуются `AI_TEST_MODEL_KIND=local|remote`, непустые `AI_TEST_MODEL_BASE_URL`, `AI_TEST_MODEL_NAME`, `AI_TEST_MODEL_API_KEY`. Для explicit local дополнительно обязательны `AI_TEST_MODEL_ID` и абсолютный `AI_TEST_MODEL_PATH`: ID сверяется с SHA-256 нормализованного пути, а работающий llama-server должен вернуть этот же путь через `GET /props` наряду с выбранным alias в `/v1/models`. Local URL обязан быть loopback, remote URL — HTTPS или принадлежащий панели loopback-прокси для усилия модели. Неполный, неверный, недоступный или не совпадающий с выбранным GGUF профиль даёт `BLOCKED` без переключения на Qwen. Live-сценарий проверяет фактический ответ выбранной модели, а не только печатает её имя.
- LTP-2. Переменные передаются только явной белой группой из `acceptance.py` дочерним live-сценариям. Без них сохраняется существующий самостоятельный локальный тестовый путь.
- LTP-3. Acceptance владеет одним собственным локальным launcher на весь набор live-сценариев и завершает его ровно один раз в `finally` даже при ошибке. Если endpoint уже запущен панелью, harness его только использует и не останавливает. Прямой `test.bat live` без acceptance сохраняет самостоятельное владение.
- LTP-4. Детерминированные поисковые сценарии сохраняют fake API. При `AI_TEST_TAVILY_ENABLED=1` и непустом `AI_TEST_TAVILY_API_KEY` добавляется отдельный реальный end-to-end модель → MCP → Tavily → ответ с URL. Отсутствие ключа или подтверждённого вызова даёт `BLOCKED`, а не fake `PASS`; без opt-in оплачиваемого вызова нет.
- LTP-5. Тестовые backend и MCP не читают рабочую `.env`. Ключи передаются только нужным дочерним процессам через env. Отчёт указывает фактически проверенные тип/имя модели, безопасный ID локального GGUF и статус поиска без ключа и полного пути. Потоки stdout/stderr дочерних процессов редактируются до записи в логи, вложенные поля отчёта — до сериализации; ключи не записываются в командную строку, stdout/stderr, trace, логи или run artifacts.

## Неприкосновенные области

Не менять настройки моделей ролей OpenCode, `opencode.json`, рабочую `.env`, продакшен-запуск, Telegram-уведомления и материалы курса вне тестового harness. Допустим лишь точечный opt-out чтения `.env` в `agent/settings.py` с неизменным поведением по умолчанию.
