# Модуль `local-llm-chat`

`local-llm-chat` — модуль курса, расположенный в каталоге `week-06/local-llm-chat`. Модуль не является самостоятельным проектом и наследует правила курсового корня.

## Что наследуется

- `AGENTS.md` курсового корня — переносимые правила агентов.
- `PROJECT_RULES.md` курсового корня — общие правила курса.
- Роли агентов и маршрутизация из курсового корня.

Модуль **не имеет** собственного `opencode.json` и собственных ролей агентов.

## Что содержит модуль

- `MODULE_RULES.md` — только дельта к правилам курсового корня.
- `MODULE_STATE.md` — состояние модуля.
- `setup.bat`, `test.bat`, `run_app.bat`, `smoke_test.bat` — доверенные точки входа модуля.
- `.env.example` — заглушки переменных окружения.
- `app/` — исходный код FastAPI-приложения.
- `harness/` — доверенный раннер сценариев и LIVE-проверки.
- `tests/unit`, `tests/integration`, `tests/scenarios` — тесты и сценарии.
- `docs/specs/day-26-local-llm/` — `SPEC.md`, `PLAN.md`, `ACCEPTANCE.md` (D26).

## Команды

Команды выполняются из каталога модуля `week-06/local-llm-chat`:

## Этап D26 — локальная Gemma 12B и сетевой DeepSeek

День 26 переносит рабочий чат и retrieval `week-05/knowledge-agent` и добавляет:

- **Двухпозиционный переключатель провайдера** ответа в UI: «Local — Gemma 12B» | «Network — DeepSeek» (без списка моделей и автообнаружения).
- **Собственный жизненный цикл локального процесса** `llama-server.exe` (единственный владелец PID; идемпотентный старт; «готово» только по подтверждённой доступности сервера; выгрузка и остановка только своего процесса; массовый kill и чужие процессы исключены).
- **Режимы RAG / no-RAG**: по умолчанию — no-RAG; RAG включается пользователем и добавляет поиск, источники и цитаты. Без-RAG не приписывает документальные источники.
- **Инструменты знания в RAG-панели**: индексация документа, поиск с `min_score`-фильтром, query rewrite (перефразирование запроса моделью с безопасным откатом к исходному), сравнение отфильтрованного и неотфильтрованного результатов и проверка цитат ответа против реально переданных фрагментов.
- **Управление диалогами в UI**: создание, переименование (Rename) и удаление (Delete) диалогов; лента сообщений, память задачи, увеличивающееся поле ввода и скрываемая правая панель.
- **Независимость от «Центра»**: приложение использует только собственные настройки и процессы; переменные `AI_TEST_MODEL_*` применяются лишь как отдельный тестовый профиль и не подменяют рабочую конфигурацию.
- **Точку подключения MCP** (описание по `week-04/day-16-mcp-agent/agent/mcp_adapter.py`) без полной интеграции.

### Архитектура `app/`

| Компонент | Ответственность |
| --- | --- |
| `app/config.py` | Собственные настройки провайдеров, портов, путей; отделение от `AI_TEST_MODEL_*`. |
| `app/providers/` | Единый интерфейс адаптера модели ответа: `local_llama.py` (llama-server), `network_deepseek.py` (DeepSeek). |
| `app/local_process/gemma_manager.py` | Владелец процесса Gemma: состояния, readiness, stop own PID. |
| `app/context/builder.py` | Сборка контекста из памяти диалога и (только в RAG) найденных фрагментов. |
| `app/rag/` | Retrieval: embedding (отдельная модель), индексация, поиск, фильтрация, query rewrite, сравнение, проверка цитат. |
| `app/dialogues/store.py` | SQLite-хранение диалогов, сообщений и памяти задачи; фактическая модель ответа. |
| `app/mcp/connection_point.py` | Описание проверенной точки подключения MCP. |
| `app/api/`, `app/ui/` | FastAPI-маршруты и статический UI (English). |

### Переменные окружения (без секретов)

Секреты — только в `.env` (не создаётся приложением). Ключевые группы настроек:

- Локальная модель: `GEMMA_RUNTIME_PATH`, `GEMMA_GGUF_PATH`, `GEMMA_MODEL_ID`, `GEMMA_PORT`, `GEMMA_CONTEXT_TOKENS`, `GEMMA_MAX_OUTPUT_TOKENS`.
- Сетевой провайдер: `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL_ID`, `DEEPSEEK_API_KEY` (только в `.env`).
- Backend: `APP_HOST`, `APP_PORT`; хранение: `DIALOGUE_DB_PATH`; embedding: `EMBED_BASE_URL`, `EMBED_MODEL`.

Backend и `llama-server.exe` используют разные loopback-порты (по умолчанию `8780` и `8791`).

### Сохранённые артефакты приёмки

LIVE-проверка (`test.bat scenario d26-acceptance`) сохраняет полные ответы, идентичность модели, параметры, времена и `usage`/`finish_reason` в `local-data/acceptance/day-26/`:
`preflight.json`, `gemma-q1.json`, `gemma-q2.json`, `gemma-q3.json`, `deepseek-q1.json` (при наличии конфигурации), `lifecycle.json`, `rag-control.json`.

### Ограничения

- Доступность `llama-server.exe`/GGUF и сетевого DeepSeek зависит от учебного окружения.
- При отсутствии конфигурации DeepSeek фиксируются конкретные недостающие параметры (без секретов); критерий DeepSeek не закрывается моком.
- Embedding-модель retrieval — независимая от модели ответа; при неизменной embedding-конфигурации индекс не перестраивается.

LIVE-сценарий загружает собственный `.env` модуля после проверки разрешения LIVE, как обычный запуск приложения. Значения секретов не выводятся. Чтение UTF-8 с BOM поддержано. Все три фиксированных вопроса реально выполняются и для DeepSeek; ошибка транспорта или содержательного ответа запрещает общий PASS. Полный preflight сохраняет ответ, модель, usage и время, не заменяясь кратким health-результатом.

Офлайн-регрессия: UNIT + INT — 51 passed. Реальный прогон: все три ответа Gemma, все три DeepSeek, Local→Network→Local, unload/reload и контроль RAG/no-RAG — PASS. Это доказательства соответствующих сценариев, а не автоматическое подтверждение всех требований.

В UI исправлены возврат скрытой панели, видимость RAG-инструментов только в RAG и доступность памяти диалога без RAG. Выбор Local явно загружает Gemma, повторный выбор после выгрузки запускает её снова; во время загрузки переключатели заблокированы. Браузерная проверка проведена на отдельной временной базе; пользовательские диалоги сохранены. Проверка D26-11 «при выключенном Центре» не подтверждается файлом lifecycle.json: он доказывает только жизненный цикл Gemma. Для полного D26 требуются отдельные фактические свидетельства этой проверки. Старые отчёты агентов сохраняются как история и не считаются свежей приёмкой после правок.

## D28 Выбор модели и документальный RAG

### Что реализовано

Без внешнего профиля список моделей рекурсивно читает `GGUF_DIR` (по умолчанию рабочий каталог моделей). `Refresh models` обновляет список. Проекторы `mmproj` исключены, путь за пределами каталога отклоняется. Доступны только реально настроенные варианты DeepSeek (`DEEPSEEK_MODEL_ID`, необязательный `DEEPSEEK_MODELS`). Выбор GGUF завершает прежний собственный runtime перед загрузкой нового; выбор сети и Unload освобождают только собственный процесс приложения. История и память диалога сохраняются в SQLite.

Полный `AI_TEST_MODEL_KIND`, `AI_TEST_MODEL_BASE_URL`, `AI_TEST_MODEL_NAME`, `AI_TEST_MODEL_API_KEY` имеет приоритет для ответа и query rewrite. KIND — local или remote; URL проходит проверку. Частичный или неверный профиль даёт явную ошибку без резервного запуска другой модели. При полном профиле UI блокирует ручной выбор и выгрузку. Для локального профиля вызывается уже арендованный внешний runtime с `X-AI-Test-Model-Lease-Id`; приложение не становится владельцем этого процесса. Опциональные ID/PATH уточняют отображаемую идентичность, секреты не выводятся. Внешний alias может отличаться от имени файла: это явно показано в UI.

### Индекс и совместимость embedding

Используется активная готовая версия `agents-survey` из `week-05/knowledge-agent/local-data/index.db`: 59 фрагментов, embeddinggemma:300m, 768 измерений. База открывается read-only; исходные тексты, ID, метаданные и векторы сохранены. UI показывает коллекцию и отключает запись в этот источник.

Проверяются модель, префиксы, размерность, float32 и L2-нормализация. При отличающемся digest установленной embedding-модели проверка воспроизводит ВСЕ сохранённые векторы и отклоняет несовместимость. В текущем окружении проверено 59/59, максимальная абсолютная разница 7.4231e-9 при пороге 1e-5. Файл: `local-data/acceptance/day-28/embedding-all-vectors.json`. Совпадение размерности само по себе не считалось доказательством.

### Чтение PDF и честность цитат

В старом индексе текст двух колонок PDF местами перемешан. Исходный индекс не исправлялся. `harness/build_reading_view.py` создаёт отдельное представление чтения исходного PDF в `local-data/day28-reading-view.json` (для регенерации нужен pdfplumber). Сохраняются SHA исходного PDF и текста фрагмента, страница и колонка. Это вспомогательная эвристика, не универсальный парсер PDF: совпадения найдены для 55 из 59 фрагментов.

В контекст сначала попадают оригинальные найденные фрагменты, затем — только при свободном бюджете — явно обозначенные выдержки из соответствующего PDF. Вспомогательная выдержка не вытесняет исходные свидетельства. Устаревшие привязки по SHA не используются. Точный отправленный контекст сохраняется в trace; DeepSeek получает те же фрагменты. Внешний демонстрационный запуск использовал RAG_MAX_CONTEXT_CHARS=48000; обычный default — 12000 символов. Это бюджет текста, не число токенов модели.

Проверка цитат проверяет существование ссылки и дословность КАЖДОЙ цитаты. Она не доказывает смысловую корректность. При неизвестной ссылке или неверной цитате допускается один запрос исправления; оба ответа сохраняются, скрытого переписывания цитат нет. `semantic_quality=NOT_ASSESSED` сохраняется до отдельной проверки. Неудача не заменяется фиктивным PASS.

Для сценария требуется разрешение LIVE по существующему `harness/live_policy.py`, работающий app по D28_APP_URL, Ollama с embedding-моделью и настроенный DeepSeek. Тесты и демонстрации использовали отдельные базы `local-data/acceptance/day-28/*demo.db`, не пользовательскую историю.
