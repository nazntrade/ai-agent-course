# Устройство и одноразовый pairing

Модель выбирается через Центр. Для устройства нужен отдельный token; провайдерский ключ пользователю приложения не показывается.

Перед локальным provisioning выполните setup. Рабочая БД должна совпадать с `APP_DATA_DIR` запущенного сервиса; обычный local/network использует `.runtime/service`. Создайте собственный `.runtime/admin-request.json`:

```json
{"schema_version":"local-admin-v1","action":"provision","owner_id":"owner-main","label":"My phone"}
```

Запустите `test.bat scenario device-provision`. Сценарий создаёт owner при отсутствии и новое устройство, записывает безопасный результат в `.runtime/admin-result.json`. Token не появляется в stdout или аргументах процесса. Зашифрованный payload находится в `.runtime/pairing/initial-device.dpapi`; папка ограничена ACL владельца, DPAPI привязан к текущему Windows-пользователю.

Не создавайте второе устройство поверх ожидающего payload. Если pairing не состоялся за 15 минут, устройство отзывается; истёкший payload удаляется при обслуживании локальной администрации. Действующий сервис также регулярно отзывает просроченные устройства в БД.

### Обычный Android APK: явная первоначальная настройка

Сначала вручную запустите `run_app.bat network` и дождитесь готовности сервиса. Затем выполните provisioning выше. Подготовьте собственный исключённый из Git `.runtime/android-normal-setup-request.json` с ровно четырьмя полями:

```json
{"schema_version":"android-normal-setup-v1","target":"normal","server_url":"http://10.0.2.2:8791","expected_device_id":"<32-lowercase-hex-from-admin-result>"}
```

Это адрес доступа эмулятора к вручную запущенному gateway. Для настоящего телефона адресом будет разрешённый частный LAN IP или HTTPS с действительным сертификатом. Нельзя добавлять userinfo, query, fragment или путь приложения. Device ID берётся из безопасного admin result; token в request не записывается.

```text
test.bat scenario android-build
test.bat scenario android-normal-setup
```

`android-normal-setup` — явный offline административный сценарий. Он не запускает gateway или модель и запрещён внутри изолированного E2E fixture. Сборка заранее проверяет пакет обычного main APK, отсутствие instrumentation в нём, compiled `targetPackage` отдельного test APK и одинаковый сертификат. Существующий обычный APK допускает совместимое обновление без очистки данных; чужой сертификат и уже установленный test APK сохраняются с ошибкой.

Перед расшифровкой DPAPI helper каждый раз проверяет свежий канал: host forward слушает только loopback, Android LocalServerSocket проверяет peer UID 0/2000 до чтения payload, а обычный app UID отвергается. Токен расшифровывается только в памяти и вводится в настоящие поля Settings; нажимается обычная кнопка Save. Проверка `/v1/me` должна вернуть точно выбранный Device ID. После подтверждения библиотека локальной администрации удаляет выбранный DPAPI payload, helper удаляет собственный test APK и forward и запускает обычный main APK через launcher. Main APK остаётся установленным.

Уже настроенный обычный APK сохраняет своё подключение: повторный setup не заменяет token, URL и данные и не расшифровывает новый payload. Неиспользованный ожидающий payload в этом случае нужно отдельно отозвать или дождаться его истечения. Результат содержит `EXISTING_CONFIGURATION_PRESERVED`, а не новое успешное pairing.

Состояние защищённого хранилища проверяется отдельно: EMPTY допускает первоначальную настройку, CONFIGURED сохраняет существующую, UNREADABLE останавливает helper до расшифровки нового DPAPI payload. Ошибка чтения или расшифровки старой настройки не считается пустым приложением. Автоматической замены повреждённых данных нет; ожидающий новый payload остаётся нетронутым.

После завершения удалите только собственный неизменённый setup request. Снимки и видео делаются после удаления helper и обычного повторного запуска, на экране беседы. Settings и одноразовый ввод token не снимаются. Android хранит token с AES-GCM и ключом Android Keystore; резервное копирование данных приложения отключено.

Для revoke замените собственный admin request:

```json
{"schema_version":"local-admin-v1","action":"revoke","device_id":"<exact-device-id-from-admin-result>"}
```

Запустите `test.bat scenario device-revoke`. Отзывается только этот ID. Другие устройства и владелец не изменяются. Следующий запрос отклоняется, SSE закрывается при ближайшей проверке revocation. Повторное включение старого токена не поддерживается; создайте новое устройство.

Никогда не передавайте `.runtime`, SQLite, DPAPI, token или provider credentials вместе с исходниками. Для теста Android создаётся отдельное scenario-owned устройство; его cleanup не затрагивает пользовательские устройства.
