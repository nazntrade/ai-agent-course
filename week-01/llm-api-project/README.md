# Запрос к LLM через API (DeepSeek)

Небольшое Web-приложение на Python и Streamlit отправляет запрос в DeepSeek API и показывает ответ модели. Приложение содержит этапы Дней 1–4: первый запрос к LLM, свободный и контролируемый (JSON) режимы, сравнение четырёх способов рассуждения и сравнение температур.

## День 1. Первый запрос к LLM

- ввод запроса через Web-интерфейс;
- подключение к DeepSeek API;
- индикатор «DeepSeek думает...» во время ожидания;
- потоковый вывод ответа по мере его получения;
- безопасное хранение API-ключа в `.env`;
- запуск приложения двойным щелчком через `run_app.bat`.

## День 2. Свободный и контролируемый режимы

- переключатель режима ответа: свободный текст или строгий JSON;
- свободный режим — обычный текстовый ответ;
- контролируемый режим — ответ строго в формате JSON с фиксированной структурой;
- ограничение длины ответа (`max_tokens`) и явное требование завершать JSON сразу после `}`;
- проверка JSON после получения: разбор и проверка структуры и типов;
- понятное сообщение при ошибке структуры или обрыве ответа;
- предупреждение, если ответ остановлен из-за ограничения длины;
- сравнение результатов: свободный ответ слева, JSON справа.

## Схема JSON (контролируемый режим)

```json
{
  "title": "string",
  "ingredients": [
    {"name": "string", "amount": "string"}
  ],
  "steps": [
    {"order": 1, "text": "string"}
  ]
}
```

## День 3. Разные способы рассуждения

- верхнеуровневый переключатель между экранами «День 2 — Формат ответа» и «День 3 — Способы рассуждения»;
- единая космическая задача оптимизации: выбор операций A–F с лимитами энергии и времени и зависимостями;
- четыре способа рассуждения:
  - **Прямой ответ** — задача отправляется без system-сообщений;
  - **Пошаговое решение** — system-инструкция решать пошагово и проверять каждый вывод и вычисление;
  - **Самостоятельный промпт** — модель сначала составляет промпт/стратегию решения (не решая задачу и не приводя ответ), затем этот промпт передаётся как system-сообщение вместе с исходной задачей; использует **два** API-вызова;
  - **Группа экспертов** — один API-вызов, в system-сообщении описаны роли аналитика, инженера и критика, которые совместно решают задачу (имитация экспертной группы в промпте, а не настоящие субагенты);
- потоковый вывод ответа и замер времени каждого способа (для самостоятельного промпта — суммарное время двух вызовов);
- детерминированная проверка ответов: перебор всех 64 комбинаций операций, валидация строки `FINAL:` и сравнение с вычисленным оптимальным решением — без LLM-судьи;
- возможность раскрыть `st.expander` и изучить реальные `messages` payload каждого запроса (`model`, `temperature`, `max_tokens`, массив `messages`);
- сравнительная таблица с итогом по каждому способу и краткие выводы.

### Выводы эксперимента

- разные способы рассуждения не гарантируют одинаковый результат;
- в записанном запуске прямой ответ и группа экспертов нашли правильное решение **A, C, F = 32**;
- пошаговый метод нашёл оптимальный вариант в рассуждении, но превысил `max_tokens` и не успел вывести обязательную строку `FINAL`;
- самостоятельно созданный промпт был подробным и корректно содержал ограничения, однако модель выдала недопустимое решение **A, B, D = 36**, превышающее ограничения по энергии и времени;
- детерминированный валидатор обнаружил обе ошибки и не позволил принять уверенные, но некорректные ответы;
- `temperature=0.2` уменьшает случайность, но не делает ответы полностью детерминированными;
- более сложный промпт не обязательно лучше простого; результаты нужно проверять независимо;
- встроенный thinking mode DeepSeek для эксперимента отключён, чтобы сравнивались именно четыре способа формирования промпта.

## День 4. Сравнение температур

- верхнеуровневый переключатель дополнен экраном «День 4 — Температура»;
- редактируемое поле `st.text_area` с готовым промптом про хранение API-ключа в публичном GitHub (ответ строго до 80 слов: один точный факт, одна короткая аналогия, три названия для памятки по 2–4 слова);
- пояснение: запрос отправляется **4 раза последовательно и независимо**; каждый вызов получает только исходный промпт, ответы предыдущих вызовов в `messages` не добавляются;
- четыре значения температуры:
  - **0** — точность и предсказуемость;
  - **0.7** — сбалансированный режим;
  - **1.2** — больше разнообразия;
  - **1.9** — экспериментальный стресс-тест, возможна потеря связности;
- во всех четырёх запросах совпадают `model`, `messages`, `max_tokens` и остальные параметры; отличается только `temperature`;
- отдельный лимит `DAY4_MAX_TOKENS = 250`; `thinking` отключён, поскольку в нём DeepSeek может игнорировать `temperature`;
- кнопка «Сравнить температуры» выполняет 4 независимых API-вызова последовательно с общим `progress bar`, указанием текущей температуры и потоковым выводом; ошибка одного запроса не останавливает остальные;
- результаты сохраняются в `st.session_state`, поэтому изменение элементов интерфейса не вызывает повторных API-запросов — повторный запуск возможен только по кнопке;
- после выполнения все 4 ответа показываются одновременно в четырёх колонках: температура и назначение, полный ответ, время, `finish_reason`, количество слов и раскрывающийся реальный payload запроса;
- ниже — компактная сравнительная таблица и ручная оценка каждого ответа по шкале 1–5 (точность, креативность, разнообразие); оценки не отправляются другой LLM;
- краткие рекомендации по выбору температуры под задачу;
- для четырёх колонок включён wide layout; экраны Дней 2 и 3 не изменялись.

## Структура проекта

- `app.py` — точка входа и диспетчер экранов: `set_page_config`, заголовок и верхнеуровневый переключатель «Этап курса». Список этапов строится из реестра `DAYS`, для выбранного этапа вызывается его `render()`-функция.
- `common.py` — общий код: константы (`MODEL`, `MAX_TOKENS`, `TEMPERATURE`, `BASE_URL`), загрузка секретов из `.env`, фабрика клиента DeepSeek `get_client()` и общий цикл потокового вывода `stream_chunks()`.
- `days/` — пакет учебных дней, по модулю на день (`day2.py`, `day3.py`, `day4.py`); каждый модуль содержит свою `render()`-функцию. Реестр этапов `DAYS` объявлен в `days/__init__.py`: чтобы добавить новый учебный день, достаточно создать `days/dayN.py` с функцией `render()` и добавить одну запись в `DAYS`.
- `tests/` — проверки без реальных API-вызовов: `test_pure.py` покрывает чистые функции (валидация JSON-рецепта, оптимальное решение космической задачи, разбор строки `FINAL`, подсчёт слов), `test_screens.py` проверяет отображение всех экранов через Streamlit `AppTest`. Запуск: `.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v`.

## Первый запуск

Откройте PowerShell в папке проекта и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

В открывшемся файле замените `your_api_key_here` своим ключом DeepSeek и сохраните файл.

## Запуск приложения

После первоначальной настройки запустите двойным щелчком:

```text
run_app.bat
```

Либо выполните в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`.

> Файл `.env` содержит секретный API-ключ и не загружается в GitHub благодаря `.gitignore`.
