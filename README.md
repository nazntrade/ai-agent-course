# AI Agent Course

Учебные задания курса по AI-агентам. Этот репозиторий хранится отдельно от других систем и переиспользуемых проектов.

## Структура

- `week-01/llm-api-project` — развивающийся проект первой недели: запросы к LLM через DeepSeek API и локальную модель (Дни 1–5).
- `week-02/first-agent` — развивающийся проект второй недели «Первый агент»: агент как отдельная сущность с инкапсулированной историей диалога, DeepSeek API, Streamlit-интерфейсом, хранением контекста в SQLite и управлением контекстом (пять стратегий на уровне чата: полная история, сводка, скользящее окно, Sticky Facts и ветвление).
- `week-03/memory-state-agent` — проект третьей недели «Memory State Agent»: явное продолжение финальной Week 2 с английским интерфейсом и явными слоями памяти (Short-term, Working, Long-term), ручными операциями Add/Edit/Promote/Forget/Include in prompt, инвариантами и наследованием слоёв при ветвлении.
- `week-04/day-16-mcp-agent` — проект четвёртой недели «MCP Agent»: вторая половина архитектуры агента — работа с инструментами по стандартному протоколу MCP. Отдельный MCP-сервер процессом (loopback, Streamable HTTP, endpoint `/mcp`) с инструментами `calculate`, `get_server_info`, веб-поиском `search_web` и инструментами фоновых заданий, CLI discovery, FastAPI-backend (health, статус MCP, список инструментов, SSE-чат, API сохраняемых чатов) и браузерный чат без сборки и CDN; локальная OpenAI-compatible модель сама выбирает инструмент. Дни 18 добавляют сохраняемые чаты (SQLite, до пяти) и периодические поисковые задания, которые выполняются планировщиком в процессе MCP-сервера независимо от открытого браузера. Есть trace в JSONL с санитайзером, harness реального lifecycle и live E2E «модель → MCP-инструмент → модель»; переиспользует общий `qa/`-runtime.
- `qa/` — общий переиспользуемый runtime изолированного Local LLM + browser E2E: единственная точка входа `qa\run_local_e2e.bat`, режимы `AUTO`/`LOCAL`/`MOCK`/`NETWORK` и `TESTS`, первая интеграция — Day 15 проекта `week-03/memory-state-agent`. Подробности — в README недельного проекта.

## Агентская разработка

Задачи в репозитории выполняет команда ИИ-агентов. Пользователь ставит задачу обычным языком и не выбирает агента сам.

- **Coordinator** анализирует задачу, маршрутизирует её между агентами и принимает результат.
- **Architect** проектирует сложные изменения, но ничего не редактирует.
- **Developer** реализует изменения и запускает проверки.

Обязательные правила работы находятся в `AGENTS.md`; курсовые правила и выбранные стеки — в `PROJECT_RULES.md`, каталог рекомендуемых стеков — в `STACK_PROFILES.md`. Конфигурации ролей — в `.opencode/agents/`.
